# Release dependencies

This app uses the existing Supabase project and authenticated Railway mobile routes. It contains no payment simulation, subscription paywall, invented entitlements, or demo CV content. Source-level integration and isolated regression coverage do not establish production or App Store readiness.

## Backend and product contracts still needed

- **Subscriptions and usage:** the supplied OpenAPI has no customer entitlement, purchase verification, or subscription lifecycle operation. The client has no store product IDs or purchase SDK. Before charging, define the monthly allowance and expose authenticated entitlement/remaining-usage state tied to the Supabase user ID. Validate store transactions on the server; handle renewals, cancellation, refunds, revocations, billing retry and grace periods. Enforce access and reserve usage atomically at paid-operation boundaries. A replay of the same tailoring job UUID must not spend allowance again. Recovery reads, reopening, ordinary edits, deterministic Job Match and PDF downloads must not start paid AI requests. StoreKit purchase/restore/manage-subscription flows and sandbox purchase tests remain required. Subscription price, duration, renewal and included value must be clear before purchase. See [Apple subscriptions](https://developer.apple.com/app-store/subscriptions/).
- **Delete account and data:** deleting one original CV is supported. There is no documented customer operation for deleting the account and all its data. Add owner-authenticated deletion that handles active workers, stored original files, registry records, jobs, previews, saved CVs, immutable editor revisions/receipts, and the Supabase identity. It needs durable completion/retry semantics and must enable account-scoped device cleanup. Do not expose service-role credentials or administrative engine routes in the client. See [Apple account deletion](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion).
- **Privacy and AI permission:** provide actual privacy, terms and support URLs, the deployed AI processor(s), data uses, retention/deletion rules, and withdrawal behavior. Obtain explicit permission before sharing personal CV data with third-party AI, including parsing during upload and keyword rewriting. These details cannot be invented from a configurable engine's OpenAPI. Complete App Store privacy disclosures, including SDK data collection. See [App Review 5.1](https://developer.apple.com/app-store/review/guidelines/#privacy).
- **Account recovery:** email/password authentication and email confirmation already exist. Password-reset/deep-link recovery and delivery must be completed and exercised with the configured Supabase redirect allowlist and actual email service before release. Supabase also reports [leaked-password protection disabled](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection); enable it in the existing project's Auth configuration.
- **Publishable mobile response schemas:** most tailoring/editor responses in OpenAPI are unconstrained objects. Keep explicit schemas for job acceptance/progress, review and keyword options, confirmation, editor/revision acknowledgements, analysis freshness/evidence, parse checks, and non-2xx errors. The app follows the repository's mobile-editor contract and preserves raw resume/preview fields. Contract changes should be versioned and covered by backend tests.

## Native and live acceptance work

- Exercise a dedicated authenticated QA account against Railway: real upload, Ready selection, one tailoring job, background/relaunch recovery, keyword attestation, complete review, confirm, edit, offline recovery, conflict handling, reopen, Job Match, actual A4/Letter PDF and downloaded-file content. Include two-account ownership denial. No credentials should be committed or put in public environment variables.
- On iPhone and Android through Draftbit Pro simulators or a build from Publishing: Files picker, token refresh after suspension, keyboard/safe-area behavior, full-length CV reading, accessibility/font scaling, PDF generation and native sharing/Save to Files. Android currently offers share-to-view rather than an embedded PDF renderer.
- Complete Publishing signing/app identity and App Store Connect product/listing/privacy/support configuration. Starter identifiers in source do not prove the published build's identity. Reviewers need working test access and reachable services.

## Preview boundary

The public Draftbit preview and published staging/production browser origins are allowed by Railway. Local screenshot-tool browser origins may be rejected by CORS; this does not establish a failure of the public preview or native networking. A signed-out screenshot cannot verify authenticated mutations or a real generated PDF. Isolated test PDF blobs verify transport/navigation logic only, not renderer quality.
